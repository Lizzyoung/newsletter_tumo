Microsoft, 에이전트 AI ‘실패 모드 분류 v2.0’ 공개
— 1년 실전 레드팀이 확인한 7개 신규 위협, “모델 평가만으로는 안 잡힌다”

📍 한 줄 요약

Microsoft AI Red Team이 2026년 6월 4일, 에이전트 AI 시스템의 실패 모드 분류(taxonomy)를 v2.0으로 갱신했습니다. 2025년 4월 v1.0이 ‘예상’ 기반이었다면, v2.0은 12개월간 실제 배포된 에이전트를 공격해 본 레드팀 실증 데이터에 기반합니다. 7개 신규 실패 모드와 5개 신규 방어 체계를 추가했고, 실전에서 가장 자주 뚫린 지점은 사람 승인 절차(HitL) 우회 — 외부 입력 하나에서 시작해 사람 개입 없이(zero-click) 데이터 유출까지 도달하는 체인이 다수 확인됐습니다.

💡 쉽게 풀면 (30초 컷)

‘에이전트 AI’는 사람이 일일이 시키지 않아도 스스로 도구(파일 읽기·웹 접속·메일 전송 등)를 골라 쓰며 일을 끝내는 AI입니다. 편리한 만큼, 나쁜 지시가 외부 입력(이메일·이슈 글·웹페이지·이미지)에 숨어 들어오면 AI가 그걸 ‘명령’으로 착각해 사고가 납니다.

Microsoft가 1년간 실제로 공격해 보니, 가장 잘 뚫린 곳은 “사람이 한 번 확인하고 승인하는 단계”였습니다. 승인 피로를 노리거나, 위험한 작업을 잘게 쪼개 개별 단계는 멀쩡해 보이게 만드는 식으로, 사람이 손도 안 댔는데 자동으로 데이터가 새는 경로(zero-click)가 여러 건 나왔습니다.

가장 중요한 한 문장은 이것입니다 — 이런 위협은 모델 하나만 따로 시험해서는 안 보이고, 여러 단계가 이어진 ‘시스템 전체’를 공격자처럼 끝까지 돌려봐야 드러납니다. 평가·레드팀의 기준이 ‘모델’에서 ‘시스템·워크플로우’로 올라가는 신호입니다.

⏱️ 왜 지금 갱신했나 — 4가지 변화

v1.0(2025/04)은 ‘위협 모델링·전문가 인터뷰’ 기반의 예측이었습니다. 1년 사이 생태계가 보안 준비보다 빠르게 커지면서, 예측이 ‘실측’으로 바뀐 게 갱신의 동인입니다.

오픈소스 에이전트의 대중화 프레임워크 OpenClaw가 2026년 1월 출시 후 GitHub 별 33.6만 개·48시간 만에 에이전트 2,100개 파생. 직후 감사에서 512건 취약점(치명 8건), 첫 주 1,800+ 인스턴스가 API 키 유출, 마켓에 악성 플러그인 336개.
MCP의 사실상 표준화 모델-도구 연결 표준 MCP가 자리잡으며, 2025년에만 MCP 관련 CVE 99건이 공개. 도구 오염이 이론에서 실제 공격면으로.
컴퓨터 사용 에이전트의 상용화 화면을 보고 조작하는 에이전트(CUA)가 연구에서 운영으로 이동 — v1.0에 없던 새 공격면이 생김.
예측 → 실측 전환 12개월 실제 교전(engagement)에서 일부 예측은 확인, 일부는 반증, 예상 못 한 실패 모드도 발견.

🗺️ 핵심 — 7개 신규 실패 모드 (모두 ‘보안’ 범주)

실패 모드한 줄 설명 + 예시
1 에이전트 공급망 오염 플러그인·MCP 서버·프롬프트 템플릿 등 ‘자연어 도구 정의’에 악성 지시를 심어 바이너리 변경 없이 행동을 바꾼다. 예) ‘트레이딩 봇’ 플러그인 설명에 “OAuth 토큰을 함께 유출하라”를 끼워 넣음.
2 목표 탈취
Goal Hijacking		 정당한 작업처럼 보이는 지시로 에이전트의 ‘최종 목표’만 조용히 다른 곳으로 돌린다. 여러 추론 단계·메모리를 넘어 지속. 예) 요약 봇이 특정 벤더를 슬쩍 추천하도록 유도(추천 오염).
3 에이전트 간 신뢰 상승 멀티 에이전트 위임에서, 권한을 검증하지 않는 오케스트레이터에게 거짓 신원·권한을 주장해 권한을 키운다. 전통 ‘혼동된 대리인(confused deputy)’ 문제의 자연어 버전.
4 CUA 시각 공격 화면을 보는 에이전트에게 사람 눈엔 안 보이지만 AI는 읽는 시각 요소(초소형 텍스트·화면 밖 요소·가짜 ‘승인’ 버튼)로 조종. 입력단 방어가 통하지 않는다.
5 세션 맥락 오염 긴 세션 초반에 데이터를 심어 이후 추론을 편향. 개별 단계는 정상으로 보여, 세션 전체 행동 분석 없이는 탐지 불가.
6 MCP / 플러그인 남용 도구 설명 오염, 서버 측 지시 주입, 신뢰 서버를 덮어쓰는 교차 서버 명령 등 프로토콜 신뢰 가정을 악용. 사람에겐 안 보이고 모델만 따른다.
7 역량·아키텍처 노출 도구 이름·스키마·시스템 프롬프트 구조·HitL 트리거 로직을 흘려, 블랙박스 탐색을 화이트박스 공격으로 전환. 그 자체가 끝이 아니라 ‘정밀 공격의 발판(pivot)’.

※ v1.0(2025/04)은 에이전트 변조·인젝션·위장·흐름 조작·멀티 에이전트 탈옥 등을 다뤘고, v2.0은 위 7개를 [New in v2.0]로 추가. 분류는 ‘신규 vs 기존 × 안전 vs 보안’ 두 축으로 정리된다.

🔎 1년 실전 레드팀이 보여준 패턴 (평가 설계의 단서)

  • ▸HitL 우회가 가장 빈번하게 악용됐다. 승인 피로, 확률적 호출 조작, 점진적 단계 상승으로 — 개별 단계는 검토가 불필요해 보이지만 합쳐진 결과는 고위험. 제로클릭 체인이 외부 입력 하나에서 유출·횡적 이동까지 도달.
  • ▸XPIA + 메모리 오염이 자주 결합됐다. 외부 콘텐츠로 들어온 인젝션이 가장 신뢰도 높은 초기 침투 경로였고, 한 번 심으면 이후 세션으로 전파.
  • ▸세션 맥락 오염·점진 상승은 탐지가 어려웠다. 어느 단계도 단독으로는 비정상이 아니라, 세션 전체 행동 분석이 있어야 잡힌다.
  • ▸역량 노출이 후속 공격의 핵심 발판이었다. 고임팩트 체인 다수가 “시스템에 직접 물어보는 것”만으로 아키텍처 정보를 얻어 시작됐다.

🎤 원문 확인 인용

“the seven new categories should be mandatory coverage areas. Zero-click HitL bypass chains, inter-agent trust escalation, and session context contamination will not be surfaced by model-level evaluation alone. They require system-level testing and multi-step attack chains evaluated across complete task flows.”

— Microsoft AI Red Team, “Updating the taxonomy of failure modes in agentic AI systems” (2026/06/04)

번역: “이 7개 신규 범주는 반드시 다뤄야 하는 영역이다. 제로클릭 HitL 우회 체인, 에이전트 간 신뢰 상승, 세션 맥락 오염은 모델 단위 평가만으로는 드러나지 않는다. 완결된 작업 흐름 전반에 걸친 시스템 단위 테스트와 다단계 공격 체인 평가가 필요하다.”

🧩 업계 표준과의 정렬 — 공통 언어에 가까워진다

v2.0은 독립적으로 만들어진 주요 프레임워크와 교차 참조됩니다 — OWASP Top 10 for Agentic Applications(ASI01~04), CSA 에이전트 AI 레드팀 가이드(62쪽·12개 위협 범주), MITRE SAFE-AI(ATLAS↔NIST SP 800-53 연결), NIST AI 600-1, CoSAI(Google·IBM·Microsoft·NVIDIA 공동) 원칙. 서로 다른 출발점의 프레임워크가 비슷한 실패 모드를 지목한다는 ‘수렴’ 자체가 위험 신뢰도의 근거이며, Datumo가 에이전트 평가를 설명할 때 참고하기 좋은 표준 지도이기도 합니다.

🎯 So What for Datumo

이 소식의 핵심은, Microsoft가 에이전트 AI 보안에서 “모델 단위 평가만으로는 부족하다”는 점을 실전 레드팀 경험을 통해 공식화했다는 것입니다. 에이전트의 위험은 단일 답변이 아니라 도구 호출, 권한 위임, 사람 승인 절차, 외부 입력 처리가 이어지는 전체 업무 흐름에서 발생합니다.

Datumo 입장에서는 독립 평가의 초점이 “모델이 정답을 냈는가”에서 “AI 시스템이 실제 환경에서 안전하게 작동하는가”로 넓어지고 있음을 보여주는 신호입니다. 특히 시스템 단위 레드팀·다단계 시나리오 평가·도구 사용 검증은 에이전트 시대에 더 중요한 차별 축이 됩니다.

📖 용어 풀이

실패 모드 분류(taxonomy of failure modes): AI가 오작동·악용되는 방식을 유형별로 정리한 지도 · HitL(Human-in-the-Loop): 위험 작업 전 사람이 확인·승인하는 안전장치 · zero-click: 피해자 행동 없이 끝까지 진행되는 공격 · MCP(Model Context Protocol): 모델을 외부 도구에 연결하는 표준 규약 · XPIA(cross-domain prompt injection): 외부 콘텐츠에 숨긴 지시로 AI를 조종하는 인젝션 · CUA(Computer Use Agent): 화면을 보고 직접 조작하는 에이전트 · SBOM: 소프트웨어 구성요소 명세서 · confused deputy: 권한 있는 주체를 속여 대신 행동하게 만드는 고전적 권한 오용.
