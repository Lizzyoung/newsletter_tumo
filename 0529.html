Anthropic, Claude Opus 4.8 출시
— 장기 실행 에이전트와 병렬 워크플로우를 전면에

📍 한 줄 요약

Anthropic은 5/28 Claude Opus 4.8을 기존 Opus 4.7과 같은 표준 가격으로 공개했고, Claude Code가 큰 작업을 병렬 서브에이전트로 나눠 수행·검증하는 Dynamic Workflows를 함께 선보였다.

💡 쉽게 풀면

이번 발표의 핵심은 “더 똑똑한 채팅 모델”보다 더 오래, 더 큰 일을 맡길 수 있는 코딩 에이전트다. Anthropic은 Opus 4.8이 전작보다 코딩·에이전트 작업 전반에서 개선됐다고 설명했고, 모델이 작성한 코드의 결함을 지적하지 않고 넘기는 비율도 Opus 4.7 대비 약 4배 낮아졌다고 밝혔다.

Dynamic Workflows는 Claude가 작업을 계획한 뒤 한 세션에서 수십~수백 개의 병렬 서브에이전트를 실행하고, 결과를 검증한 뒤 하나의 답으로 정리하게 하는 기능이다. 연구 프리뷰 단계이며, 일반 Claude Code 세션보다 사용량이 크게 늘 수 있다.

📊 공식 발표에서 확인되는 핵심 사실

항목 확인된 내용
출시·가격 5/28 출시. 표준 사용료는 Opus 4.7과 동일한 입력 $5 / 출력 $25 per 1M tokens. Fast mode는 입력 $10 / 출력 $50.
품질·정렬 Anthropic은 작성 코드의 결함을 지적 없이 통과시키는 비율이 전작 대비 약 4배 낮아졌다고 발표.
Dynamic Workflows Claude Code에서 큰 작업을 수십~수백 개 병렬 서브에이전트로 나눠 수행하고, 결과를 검증·통합하는 research preview 기능.
Dynamic Workflows 제공 범위 Opus 4.8 모델 자체는 전 채널에 즉시 제공. Dynamic Workflows는 Claude Code CLI·Desktop·VS Code extension의 Max·Team·Enterprise(관리자 활성화 필요 시) 플랜과 API·Amazon Bedrock·Vertex AI·Microsoft Foundry에서 research preview로 제공.
주의점 Dynamic Workflows는 일반 Claude Code 세션보다 토큰 사용량이 유의미하게 늘 수 있다고 Anthropic이 명시.

정확도 주의: 초안의 세부 벤치마크 순위·타사 대비 우위·“최대 1,000개 서브에이전트” 표현은 본문에서 제외했다. 공식 공개 글에서 직접 확인되는 설명은 성능 개선과 수십~수백 개 병렬 서브에이전트이며, 벤치마크가 실제 고객 업무 성능을 그대로 보장하지는 않는다.

🎯 Datumo 관점에서의 맥락

Opus 4.8보다 더 중요한 변화는 평가 단위가 한 번의 답변에서 장기 실행 워크플로우로 넓어진다는 점이다. 수십~수백 개 서브에이전트가 작업을 나누고 다시 합치는 환경에서는 최종 정답률만으로 품질을 설명하기 어렵다.

Claude Code Security Guidance
— 코드 작성 중 보안 검토를 기본 흐름으로

📍 한 줄 요약

Anthropic의 Security Guidance 플러그인은 Claude가 작성하는 코드를 편집 시점·턴 종료 시점·Claude가 수행하는 커밋/푸시 시점에 검토한다. 전 플랜에서 사용 가능하지만, 모델 기반 검토는 일반 요청처럼 사용량을 소비한다.

💡 쉽게 풀면

Claude Code가 코드를 만든 뒤 나중에 별도 검사를 기다리는 대신, 코드를 작성하는 세션 안에서 위험 신호를 먼저 잡고 수정하도록 돕는 플러그인이다. 파일 편집 직후에는 위험 함수나 DOM injection 같은 패턴을 빠르게 찾고, 턴 종료 단계에서는 별도 Claude 검토가 변경된 git diff를 살피며, Claude가 커밋·푸시하는 단계에서는 주변 코드·sanitizer·관련 파일까지 읽는 더 깊은 검토가 이뤄진다.

다만 이 기능은 보안 승인 게이트가 아니다. 공식 문서는 플러그인이 쓰기나 커밋을 차단하지 않으며, 놓치는 취약점이 있을 수 있으므로 정적 분석·의존성 스캔·CI 정책과 함께 써야 한다고 명시한다.

📊 작동 구조와 비용 — 공식 문서 기준

시점 무엇을 하는가
파일 편집 시 모델 호출 없이 위험 패턴을 매칭. eval(), unsafe deserialization, DOM injection 등 예시가 공식 문서에 명시됨. 추가 사용 비용 없음.
각 턴 종료 후 변경된 git diff를 별도의 Claude 리뷰가 검토. authorization bypass, IDOR, SSRF, weak cryptography 등 맥락형 문제를 찾을 수 있음.
Claude의 commit/push 시 주변 코드·sanitizer·관련 파일까지 읽는 더 깊은 agentic review. 사용자가 직접 실행한 shell commit은 검토 대상이 아님.
요금·사용량 플러그인은 전 플랜에서 제공. 패턴 매칭은 비용이 없지만, 턴 종료·커밋 검토는 추가 Claude 사용량으로 계산됨.
요구 환경 Claude Code CLI 2.1.144 이상, Python 3.8 이상. 턴 종료·커밋 검토는 git repository에서만 동작.

정확도 주의: 공식 문서는 취약점 클래스의 총수를 “약 25개”로 제시하지 않는다. 또한 30~40% PR 보안 코멘트 감소는 Anthropic이 내부 도입·벤치마크 기준으로 발표한 수치이며, 외부 검증 결과가 아니다.

🎯 Datumo 관점에서의 맥락

모델 공급사가 코딩 세션 안에 보안 검토를 기본 기능처럼 제공하면, 단순한 “생성 코드의 1차 취약점 검사”는 독립 평가사의 차별점이 되기 어려워진다. 특히 글로벌 고객은 이미 사용하는 개발 도구 안에서 가장 빠른 1차 검토를 받으려 할 가능성이 크다.

Datumo가 가져갈 수 있는 자리는 그 바깥이다. 모델·코딩 도구에 종속되지 않는 검증, 조직별 보안 정책과 규제 기준의 매핑, 실제 에이전트 행동·산출물에 대한 감사 가능 리포트가 필요하다. 즉, 벤더 내장 기능과 경쟁하기보다 여러 벤더를 가로질러 “도입 가능한 수준인지” 판단해주는 독립 평가 레이어로 가는 것이 글로벌 포지션에 더 가깝다.
