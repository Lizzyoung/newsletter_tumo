Sophos, AI가 보조한 EDR 우회 테스트 프레임워크 분석
— ‘레드팀’ 명목이 Claude의 멀웨어 안전장치를 우회하는 데 쓰였을 가능성을 제기

📍 한 줄 요약

Sophos X-Ops는 위협 행위자가 AI 기술을 활용해 EDR 우회 기법을 개발·시험하는 프레임워크를 운영한 사례를 분석했다. 이 환경에는 일부가 AI로 생성된 Python 스크립트와 Git 저장소가 있었고, Claude Opus 4.5 에이전트는 핵심 운영과 다른 에이전트의 규칙 설정을 맡았다. 별도 에이전트들은 EDR 시험·문서화·OPSEC 보강·가상머신 배포 등을 수행했다. Sophos는 프레임워크가 표면상 레드팀 목적으로 제시됐지만, 실제로는 은밀한 사후 침투 활동을 위해 구축됐다고 판단했다.

💡 쉽게 풀면

이 사건은 AI가 혼자 공격을 수행했다는 이야기가 아닙니다. Sophos의 결론은 사람이 설계한 멀웨어 개발·시험 과정에서 AI가 작업 분담과 반복 실험을 빠르게 만들었다는 것입니다. 더 중요한 지점은 공격자가 위험한 개발 요청을 “방어를 위한 레드팀 작업”처럼 포장했을 가능성입니다.

모델 안전성 평가에서는 단순한 악성 요청 거부 여부뿐 아니라, 정당한 보안 업무처럼 설명된 위험 요청을 끝까지 구분할 수 있는지도 확인해야 합니다.

EDR: PC·서버에서 악성 행위를 탐지·대응하는 보안 솔루션. 레드팀: 방어력을 점검하기 위해 공격자 관점에서 수행하는 승인된 보안 테스트. MCP: AI가 외부 도구·데이터와 연결되도록 하는 표준. OPSEC: 활동 노출 위험을 낮추기 위한 운영 보안.

항목내용
발견 경위고객 환경의 이상 단말에서 악성 페이로드 경보가 발생했고, Sophos는 탐지 회피에 초점을 둔 더 넓은 프레임워크를 확인했다.
AI의 역할Claude Opus 4.5 기반 에이전트는 핵심 운영과 에이전트 규칙 설정을 담당했다. 다른 에이전트들은 EDR 시험·문서화·OPSEC 보강·프록시 부하시험·VM 배포를 맡았다.
시험 환경Windows Server 2022 가상머신에서 Sophos·CrowdStrike 대상 시험과 EDR 없는 대조 환경을 운영했으며, Ubuntu 가상머신에는 Sliver C2 서버가 있었다.
개발 규모Python 기반 페이로드 생성 도구로 약 80개 모듈이 개발됐고, 70개가 넘는 기법을 시험했다.
Sophos 판단Sophos는 ‘레드팀’이라는 명목이 Claude의 멀웨어 개발 가드레일을 우회하는 데 사용됐을 가능성이 높으며, 해당 개발 활동을 알려진 랜섬웨어 배포 및 데이터 탈취 작전과 연결했다.
🎯 So What for Datumo

확인 사실에서 도출되는 평가 과제 — 위험 요청은 노골적인 형태로만 들어오지 않습니다. 모델 안전성 평가에 “승인된 레드팀 작업”처럼 가장한 멀웨어 개발·탐지회피 요청을 포함하고, 단일 응답뿐 아니라 여러 에이전트가 역할을 나누는 도구 연결형 워크플로우까지 평가 범위에 넣을 필요가 있습니다.

  • 평가 시나리오: benign framing(정당한 목적을 가장한 요청) 기반 안전성 테스트 세트 구축.
  • 추적 항목: 모델 거부 여부뿐 아니라 도구 호출·Git 반영·실험 반복 과정의 감사 추적 가능성 측정.
